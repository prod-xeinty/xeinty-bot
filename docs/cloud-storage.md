# XEINTY: облачное хранение для MVP

## Что хранится

- В Supabase: карточка бита, тексты публикаций, ссылки, компактная обложка и MP3 для прослушивания.
- На устройстве автора: исходный WAV, stems и другие рабочие файлы. При экспорте автор выбирает исходник повторно, если он нужен.
- MP4 собирается в браузере из аудио и обложки. После сохранения на устройство облачная копия не создаётся.

## Доступ

Mini App передаёт серверной функции оригинальную строку `Telegram.WebApp.initData`. Функция проверяет подпись через секрет бота, срок действия и Telegram ID пользователя. Клиент не получает секрет бота или ключ администратора Supabase. Все операции с карточками и приватными файлами проходят через эту функцию; записи фильтруются по проверенному Telegram ID. Для передачи MP3 и обложки функция выдаёт короткоживущие подписанные ссылки.

## Ограничения пилота

Supabase Free сейчас включает 1 ГБ файлового хранилища, 500 МБ базы и 5 ГБ исходящего трафика плюс 5 ГБ кешированного. Бесплатный проект засыпает после недели бездействия. Поэтому для первых пользователей ограничиваем размер MP3 и обложки, а тяжёлые WAV и MP4 не загружаем.

## Переход с локальных данных

Уже сохранённые в IndexedDB биты нельзя удалять при подключении облака. После входа через Telegram приложение должно предложить явный перенос каждого локального бита в облако. До подтверждённого переноса локальная запись остаётся доступной. Сохранение в облако из обычного браузера без Telegram-подписи не выполняется.

## Подключение

1. Создать отдельную организацию XEINTY и проект Free в Supabase.
2. Применить миграцию `supabase/migrations/0001_beats.sql`.
3. Добавить `TELEGRAM_BOT_TOKEN` в Secrets проекта через панель Supabase. Токен не помещать в репозиторий и не отправлять в чат.
4. Развернуть функцию `beats` с проверкой Telegram `initData`.
5. В GitHub Repository variables добавить `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`. Это публичные значения; секрет бота там хранить нельзя. Для локальной проверки заполнить `.env.local` по образцу `.env.example`.
6. Протестировать сохранение, прослушивание, перенос старого бита и удаление на двух устройствах, затем обновить GitHub Pages.
